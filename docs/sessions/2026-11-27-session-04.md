## Device bring-up & crackle hunt
- Installed over Wi-Fi adb (USB adb fails through the Mac's hubs). Native button bridge verified (A..START = indices 0–9, sticks OK); WebView Gamepad API sees nothing.
- User report: crackle / "like changing the buffer in Ableton", laggy. Ruled out: DSP/effects (RAW A/B identical), engine output (in-app recordings clean), main-thread jank (no long tasks, 0 late steps), buffer size (TIGHT/LIVE/SAFE all bad).
- Confirmed: Chrome 158 on the device plays the same live code cleanly. Firmware allows only `com.android.webview` 113 (no Google WebView switch).
- Root cause measured: the app's context ran at 0.34× real time; fresh contexts without worklets 1.0×; adding a worklet hangs/slows it. → `WORKLETS_OK` guard (commit 3a904ae), untested on device.
- Built `NativeAudioOut` (AudioTrack + ring buffer) + worklet tap: works but useless while the context itself is throttled.
- Live dev workflow (`npm run device:dev`), dev-only `__bus` A/B hook in DRUM-8.
- Chrome sees the controls as non-standard `retrogame_joypad` (17 buttons, 6 axes); mapping capture not completed.

- LAST TEST: WORKLETS_OK=false → still 0.37×; limiter disconnected → 0.378×. Worklet theory disproved; the throttle is something else in the app context (bisect next).
